What Happens When You Type https://www.google.com and Press Enter

End-to-end request flow: DNS -> TCP/TLS -> Firewall -> Load Balancer -> Web/App/DB -> response to browser

Flow Notes

Solid arrows: request path going down.

Dashed arrow: response path returning up.

HTTPS is encrypted after TLS handshake and certificate validation.

1) Browser (Client)

User enters https://www.google.com and presses Enter.

2) DNS Resolver

Browser asks configured DNS resolver for www.google.com.

3) Root DNS Servers

Resolver queries Root to discover where .com TLD servers are.

4) TLD DNS (.com)

Resolver queries TLD to find Google's authoritative DNS servers.

5) Authoritative DNS

Authoritative server returns the IP address for www.google.com.

6) TCP Connection (Port 443)

Browser establishes TCP session to returned server IP on port 443.

7) TLS Handshake + Certificate Validation

Browser verifies certificate; encrypted HTTPS channel is negotiated.

8) Firewall

Traffic is inspected and HTTPS on 443 is allowed to pass.

9) Load Balancer

Request is routed to the least-busy healthy backend server.

10) Web Server (Nginx/Apache)

Serves static assets and forwards dynamic requests to app server.

11) Application Server

Builds dynamic response logic and requests required data.

12) Database

App server queries DB; DB returns records used for response rendering.
